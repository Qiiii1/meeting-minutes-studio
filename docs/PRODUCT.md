# 会记 Minutes · 产品原型说明

## 定位

面向个人和小团队，从会议录音或文字得到可核对、可编辑、可导出的纪要。核心价值是把讨论变成明确决策和可执行事项。

## 当前交付

1. 会议列表：虚构示例、搜索、状态筛选、会议数量、新建入口。
2. 新建对话框：文字 / 录音入口、标题、日期、会议类型。
3. 会议工作台：原文与纪要对照、按来源跳转、手动编辑、自动保存、待办管理。
4. 行动清单：汇集会议行动项、勾选完成、返回会议。
5. PDF 预览：商务与正式样式、浏览器打印保存 PDF。
6. 数据操作：JSON 备份、删除会议、本地持久化。

示例是虚构的产品会议；演示时长与时间戳是预设值，没有示例录音。其他示例卡片用于演示状态与会议分类，不代表独立真实转写。

## 交互约定

- 用户内容使用文本转义，渲染时不执行 HTML。
- 文本输入只创建手动草稿，不输出伪造摘要。
- 原文检索是简单子串匹配；示例来源按钮定位到相关讨论片段，不代表逐条 AI 证据验证。
- 草稿 → 人工确认 → 已确认；再编辑纪要字段时恢复待确认。
- 行动项完成状态可以在确认后更新，PDF 导出始终反映当前状态。
- 录音只通过 Blob URL 在当前页面播放，不保存在 localStorage。
- 模板类型在原型中作为元数据；实际不同类型的生成规则在生产版实现。
- 原型的来源片段不可编辑，导入的原文可以编辑。

## 后续真实 API 链路

浏览器 → 业务 API → 后台任务 → 讯飞转写 → 星火整理 → 结构校验 → 用户确认 → PDF 渲染。

GitHub Pages 仅部署静态网页。真实能力需独立后端，建议 Node.js Worker + PostgreSQL + Redis 队列 + 私有对象存储。开始时可用单实例任务服务，生产多人版再扩展。

### 讯飞 LFASR

- APP_ID 和 Secret Key 保存在服务端环境变量。
- prepare → 按顺序上传分片 → merge → 持久化 task_id。
- Worker 查询进度，遵循文档建议和限额；只有状态为 9 才读取最终结果。
- 存储原文句段、发言人编号、起止时间，前端按句段回听。
- 失败只重试对应阶段，避免重复上传、重复收费。

### 讯飞星火

- APIPassword 和所开通模型、接口地址在后端配置。
- 基于 meeting-notes 思路维护版本化提示词。
- 明确要求输出结构化 JSON，后端做字段、类型和来源编号校验；不假设模型始终返回合法 JSON。
- 长会议按 token 预算分段抽取，最终合并去重并保留来源。
- 负责人、日期、结论没有依据则标记待确认；禁止把建议写成决定。
- 用户编辑稿与生成草稿分开保存，重新生成不覆盖人工修改。

### PDF

- 固定 HTML/CSS 模板承载经过确认的结构化数据。
- 服务端 Chromium 渲染，部署中文字体，等待字体加载完成。
- 版本关联、中文、长表格、跨页标题和超长纪要都需要单独验收。

## 上线前补齐

登录和会议级访问控制、私有文件存储、数据删除与保留期限、任务恢复、用量计费观测、文件校验、服务端限流和异常处理。

## 验收基线

- 8–10 份经授权会议样本，覆盖多人、长会议、术语密集与低音质。
- 人工标注决策和待办，检查抽取遗漏、误判及证据对应。
- 刷新不丢任务，编辑不丢内容；导出失败可单独重试。
- PDF 中文可复制、字体正确、表格完整，内容与确认版本一致。
